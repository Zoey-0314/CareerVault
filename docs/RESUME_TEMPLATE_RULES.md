# CareerVault resume template rules

This file records layout rules extracted from the user-provided reference resume. It intentionally does **not** copy or store any personal data from the reference file.

## Generation gate

- A resume is not generated until a target JD has been pasted.
- Resume selection, ordering, summary, bullets, and credentials must all be derived from the target JD plus verified CareerVault facts.
- If no stored experience matches the JD, show an explicit evidence-gap state instead of filling the page with unrelated experience.

## One-page density

- Target: one A4 page.
- Use 2-3 selected experiences, normally 1-3 bullets each.
- A single project must never expand into a repository changelog or technology inventory.
- Each bullet should express one contribution/evidence chain and stay concise.
- Prefer the most JD-relevant action, result, scale, method, or verified fact. Remove setup details, package names, branch history, generic tooling lists, and implementation trivia unless the JD explicitly values them.

## Reference layout (format only)

- Header: name and target-position line on the left; contact basics under them; reserved portrait box on the right.
- Section headings: low-saturation gray bar with Chinese section title plus optional small English label.
- Body sections: compact two-column rhythm, with dates/role metadata on the left and organization/content on the right.
- Recommended order: Education -> Relevant Experience -> Campus/Projects when relevant -> Awards/Certificates -> concise Professional Summary or Self-evaluation only when supported by evidence.
- Black/gray typography, high whitespace discipline, no decorative color blocks.

## Word export

- Export must be a real `.docx` file, not HTML renamed as Word.
- Word output follows the same section hierarchy and photo placeholder as the web preview.
- All values come from the current CareerVault vault at export time.
